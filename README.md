# Cafe Menu SaaS — полный проект

Три части:

```
server/        Node.js + Express + PostgreSQL API (полностью готов, детально протестирован)
admin-panel/   Панель Admin/Super Admin — React + Vite + Tailwind
client-menu/   Публичное клиентское меню — React + Vite + Tailwind
```

## Деплой в продакшен

Готовые конфиги (`render.yaml`, `netlify.toml` в обеих папках фронтендов) и
точная пошаговая инструкция — в [`DEPLOY.md`](./DEPLOY.md). Паттерн тот же,
что в твоих прошлых проектах: Neon (Postgres) + Render (бэкенд) + Netlify
(оба фронтенда), всё на бесплатных тарифах. Я подготовил и проверил все
конфиги локально (продакшен-команда запуска `npm run start:prod` реально
гоняет миграции и поднимает сервер), но зайти на сами хостинги за тебя не
могу — там нужны твои аккаунты.

## Быстрый запуск (3 терминала)

**1) База данных и API**
```bash
cd server
cp .env.example .env      # впишите свои значения, особенно SUPERADMIN_*
npm install
npm run migrate
npm run seed:superadmin
npm run seed:demo         # опционально: демо-кафе "Чайхона Восток" с 10 блюдами
npm test                  # опционально: 15 автотестов на отдельной *_test БД
npm start                 # http://localhost:4000
```

**2) Админ-панель**
```bash
cd admin-panel
echo "VITE_API_BASE=http://localhost:4000" > .env
npm install
npm run dev                # http://localhost:5173
```
Откройте, зарегистрируйте кафе → добавьте категории/блюда → «Опубликовать меню».

**3) Клиентское меню**
```bash
cd client-menu
echo "VITE_API_BASE=http://localhost:4000" > .env
echo "VITE_CAFE_SLUG=<slug вашего кафе из панели>" >> .env
npm install
npm run dev                 # http://localhost:5174
```
Slug кафе виден в админ-панели на вкладке «Ссылки».

## Честный статус

**Бэкенд** — построен и проверен вживую: полный CRUD на все сущности из ТЗ,
tenant isolation (проверено атаками между кафе), JWT + ротация refresh-токена,
брутфорс-защита, публикация/черновик меню, загрузка изображений, статистика,
impersonation для Super Admin. Подробности и список реально прогнанных
сценариев — в `server/README.md`.

**Клиентское меню** — все экраны из ТЗ реализованы: верхняя панель со
статусом, карусель рекламы, круглые категории, блоки меню, сетка блюд 2×2,
модальное окно блюда с атрибутами, плавающая круглая зелёная кнопка заказа,
галерея, контакты. Дизайн — тёплый крем + лесной зелёный + шрифты
Fraunces/Manrope (осознанный выбор, не дефолтная AI-палитра). Собирается без
ошибок (`npm run build`), реально забирает и рендерит демо-меню — это
подтверждено прямым обращением к API из кода приложения и сверкой ответа
(10 блюд, 5 категорий, всё как в базе).

**Админ-панель** — все разделы ТЗ: категории, блюда (с атрибутами/
переводами/метками), блоки меню (с подбором блюд, дублированием), реклама,
галерея, контакты, дизайн (пресеты + цвета), настройки (тумблеры, статус,
часы работы, языки), ссылки/QR, живой предпросмотр черновика, кнопка
публикации, панель Super Admin (блокировка, восстановление, вход как админ).
Собирается без ошибок.

**Чего не смог проверить и почему** — не смог сделать реальные скриншоты
или полноценный end-to-end тест в браузере: в этой песочнице нет доступа к
загрузке headless-браузера (Chromium/Puppeteer упираются в 403 от домена
загрузки — сеть ограничена только определённым списком доменов, не включая
CDN браузерных бинарников). Это значит: HTML/CSS/JS собираются без ошибок,
API-слой протестирован десятками реальных запросов, но **финальную
визуальную проверку в браузере нужно сделать вам** — команды выше займут
пару минут. Если увидите что-то не так — присылайте, поправлю.

## Что было закрыто по твоему запросу «дожать до 100%»

- Автотесты бэкенда (15 сценариев) — теперь на **отдельной тестовой БД**
  (`npm test` создаёт `<имя>_test` и никогда не трогает твою dev-базу — это
  само по себе было найдено и исправлено как баг: первая версия тестов
  чистила общую базу)
- Журнал действий — теперь есть страница в админке (не только запись в БД):
  для Admin — свои действия, для Super Admin — вся платформа
- Реальный drag&drop (HTML5, не только стрелки ▲▼) — категории, реклама,
  галерея, контакты, блоки меню
- Переключатель языка на клиентском меню — реально показывает перевод
  названия/описания блюда (ru/tg/en), не просто настройка в админке
- Поиск блюд, избранное (localStorage, без регистрации гостя), кнопка
  «Поделиться» (Web Share API с fallback на копирование ссылки) — на
  клиентском меню, у всех есть выключатели в настройках
- Автосохранение с индикатором «Сохраняем…/Сохранено» — в редакторе блюда
- Найден и исправлен реальный баг: анимации в модалке блюда ссылались на
  несуществующие Tailwind keyframes (`fadeIn`/`slideUp` нигде не были
  объявлены — визуально анимации просто не работали); добавлены + новая
  сигнатурная пульсация на кнопке заказа + скелетон-загрузка меню
- Найден и исправлен баг упаковки: `react-dom` случайно оказался в
  devDependencies (после моего собственного тестового скрипта) — вернул в
  dependencies
- Воспроизводимые демо-данные: `npm run seed:demo` — раньше демо-кафе
  собиралось разовыми командами и терялось между сообщениями

## Честно: что физически не смог закрыть в этой песочнице

- **Реальные фотографии блюд** — вместо них SVG-заглушки с эмодзи. Нет
  доступа в интернет к стоковым фото (сеть ограничена списком разрешённых
  доменов). Загрузка твоих собственных фото через админку при этом
  полностью рабочая и протестированная.
- **Скриншоты/визуальная проверка в браузере** — по той же причине (нет
  доступа к загрузке headless-браузера). Проверено иначе: живые HTTP-сценарии,
  автотесты, чистая сборка обоих фронтендов.
- **Деплой на реальный сервер** — у меня нет доступа к Render/Neon/Netlify
  или другому хостингу из песочницы. Могу подготовить конфиги по образцу
  твоих прошлых проектов (sugar-erp, exchange-crm) — просто попроси.
- **Реальная система заказа/корзины** — кнопка и её иконка на месте, но это
  явно исключено из первой версии в твоём же исходном ТЗ (пункт 36).
